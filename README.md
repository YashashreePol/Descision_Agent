# Descision_Agent

A deterministic, rule-based customer support agent built with **LangGraph** that classifies user requests into **Billing**, **Technical**, or **General** categories and provides structured, helpful responses — all without using an LLM for routing or decision-making.

---

## ✅ Features

- **Deterministic Routing**: Uses explicit keyword-based rules (no LLM) to classify requests.
- **Structured Workflow**: Follows a strict pipeline:  
  `Chat → Validation → Decision → Handler → Result → End`
- **Robust Error Handling**: Detects incomplete inputs and asks for missing details.
- **Loop Support**: Any node can request more information and return to the chat interface.
- **Centralized Output**: Final response is always generated by a dedicated `result_node` (as per boilerplate).
- **No External Dependencies**: Runs without API keys or internet access.

## 🧠 How It Works

1. **Chat Node**: Greets the user or requests missing information.
2. **Validation Node**: Checks if the input is clear and complete.
3. **Decision Node**: Classifies the request using keyword matching:
   - **Billing**: `invoice`, `refund`, `payment`, `charged`
   - **Technical**: `crash`, `error`, `bug`, `not working`
   - **General**: Everything else
4. **Handler Nodes**: 
   - Validate internal completeness (e.g., billing needs an invoice ID)
   - If incomplete → ask for more info and loop back to chat
   - If complete → store structured response in state
5. **Result Node**: Reads the handler’s response and generates the final output.
6. **End**: Workflow terminates cleanly.

All intermediate data is stored in shared state (`DecisionWorkflowState`).

## 📜 Compliance

This implementation strictly follows the **M3.2 - Decision Agent** boilerplate:

- ✅ Deterministic, rule-based classification  
- ✅ Single interaction gateway (`chat_node`)  
- ✅ Non-overlapping handler responsibilities  
- ✅ Missing info → back to `chat_node`  
- ✅ Final output only from `result_node`  
- ✅ All data stored in shared state

## 🛠️ Customization

To extend the agent:

- Add new keywords in `decision_node`
- Update validation logic in handlers
- Modify response templates in handlers
- Add new categories (requires new handler + router update)

> ⚠️ Do not add LLM calls — this agent must remain deterministic.
